# 立体感知交互实验室：D09 / D10 / D12 网页技术方案

版本：v1.0  
日期：2026-10-22  
用途：供后续 Codex 开发、验证和打包；目标为本地运行及 GitHub Pages 静态部署。  
状态：技术与交互设计稿，尚未开发网页工程或进行浏览器实测。

## 1. 产品定位与已确定的方向

把 D09“深度线索控制室”、D10“强迫透视片场”、D12“机位与焦距拆解台”做成一个统一的**自由探索式三维网页实验室**。打开后直接出现可操作场景，随时拖动物体、改变机位、切换环境线索、保存对照。

**设计重点是丰富交互和即时视觉反馈。**不设置必经教学步骤、答题提交、顺序解锁或闯关；解释和探索建议放在可展开的辅助卡中。

每次操作至少同时带来两类反馈：主画面的变化，以及空间结构、投影标记、数值或曲线的对应变化。让使用者能够追踪“我改了什么，画面为什么变成这样”。

| 模块标签 | 核心体验 | 最具辨识度的操作 | 主要反馈 |
| --- | --- | --- | --- |
| 深度线索 · D09 | 用同一片场比较不同深度线索 | 拖动近远、切换纹理/阴影/雾/遮挡、补偿画面大小 | 取景、真实排列、投影尺寸、横移轨迹 |
| 错位片场 · D10 | 亲手制作与拆解强迫透视 | 对齐接触点、沿视线移远并放大、侧移机位 | 对齐误差、原/现位置虚影、参考视点、视点误差地图 |
| 机位与焦距 · D12 | 区分原地变焦、机位变化与联动 | 分别调焦距/距离、保持主体画面高度、拖动推拉变焦时间轴 | 视场角、视锥、主体占比、前后景比例曲线 |

“立体感知”在这里指画面中的深度和空间感知。首版面向普通单屏浏览器，呈现透视、遮挡、大小关系和运动视差；它不等于向左右眼分别送图的双眼立体显示。

### 1.1 首版交付范围

- 三个完整模块，共用界面、测量工具、快照、撤销、导入导出与渲染底座。
- 主取景、空间解释视图、参数面板联动；桌面端同时可见。
- 12 个明确参数化预设，每模块 4 个；每个预设都允许继续编辑。
- 三类预设动画，支持播放、暂停、拖动进度、改变速度。
- A/B 静态对照、拖动分割线、参数差异列表、PNG 与 JSON 导出。
- 本地保存、复制可复现链接、根路径和仓库子路径部署。

首版资产以程序生成的地面、门框、色卡、托架、球体和几何人偶为主。后续精细模型作为替换资产接入；数学验收始终保留标准几何场景。

## 2. 整体界面

### 2.1 桌面布局

目标优先适配 1440×900、1920×1080；1366×768 下主要操作仍可用。网页首屏就是实验工作区，不额外设置介绍落地页。

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 立体感知 · 空间实验室  [深度线索] [错位片场] [机位与焦距]   保存 / 全屏 │
├────────────────────────────────────────────┬────────────────────────┤
│ 主取景 · 拍摄相机                           │ 当前模块控制            │
│ 固定16:9画幅，选中轮廓、投影锚点、可选标尺   │ 预设缩略图               │
│                                            │ 物体 / 机位 / 环境       │
│ [画面辅助] [存为A] [存为B] [A/B对比]         │ 滑块＋数值＋单位         │
├────────────────────────┬───────────────────┤ 自动联动状态             │
│ 空间关系                │ 即时反馈          │ 恢复预设 / 撤销 / 重做   │
│ [俯视] [侧视] [自由观察] │ 距离、占比、误差  │                         │
│ 相机模型、视锥、物体    │ 当前模块图表      │ 可折叠的原理说明         │
├────────────────────────┴───────────────────┴────────────────────────┤
│ [播放] ───────── 时间轴 ───────── 速度   当前操作与边界提示            │
└─────────────────────────────────────────────────────────────────────┘
```

- 右侧控制区宽度约 300–336 CSS px；工作区使用剩余宽度。
- 主取景保持 **16:9 成像框**，布局不足时留边，不能因窗口变窄就改变相机画幅。
- 默认显示主取景、一个较小的俯视图和当前模块核心指标；完整视锥、所有标签、误差曲线按需展开。
- “专注画面”隐藏控制面板和空间视图；“空间分析”放大解释视图；均不改变拍摄相机或场景。
- 当前模块中保留最近编辑状态；切换标签不会自动恢复预设。每个模块独立保存状态，防止 D10 的约束影响 D12。

### 2.2 视觉风格

界面使用深蓝灰底色、暖白正文、金黄色主操作，与现有课程视觉方向呼应。空间参照使用青色虚线，当前对象使用金黄描边，A/B 用不同线型和文字共同标记。

渲染场景采用中性背景、清晰轮廓、适量柔和阴影；不会把全场景做成密集发光线框。选中态、参考态、实际几何分别可辨认，颜色之外保留 A/B/C、图标和线型。

正文默认 16px，数值采用等宽数字；投屏模式放大到约 18–20px。公式默认收起，使用者首先看到“物体高度”“离相机多远”“占画面多少”等直接标签。

### 2.3 响应式与操作入口

| 可用宽度 | 布局策略 |
| --- | --- |
| ≥1280px | 主取景、空间关系、反馈区、右侧参数同时显示 |
| 900–1279px | 参数区收窄；下部空间关系与图表通过标签切换 |
| <900px | 主取景在上；参数与空间视图切换显示，避免挤成三个小窗 |

触屏提供滑块、数值输入、方向按钮；不要求使用右键或修饰键。所有悬停解释都可通过点击信息按钮访问。

## 3. 统一交互规则与反馈层级

### 3.1 三种相机身份

1. **拍摄相机 `shotCamera`**：决定主取景。焦距、位置、朝向变化都必须反映在控制区。
2. **观察相机 `inspectCamera`**：只决定空间解释视图。绕行、放大、俯视等操作不会改变主取景。
3. **参考相机 `referenceCamera`**：D10 保存的校准条件，是不可被当前拖动悄悄覆盖的数据快照；显示为青色相机虚影。

主取景上方始终注明“拍摄相机”；空间视图注明“观察空间”。首版不设置将观察相机一键覆盖拍摄相机的隐式行为。

### 3.2 输入约定

| 输入位置与操作 | 执行动作 | 即时反馈与限制 |
| --- | --- | --- |
| 主取景单击物体 | 选中物体 | 轮廓、对象名、参数卡同时高亮 |
| 空间视图拖动平面/轴向手柄 | 修改指定物体位置 | 操作平面、原位置虚影、位移；其余轴锁定 |
| 右侧“近—远”滑块 | 修改所选物体光轴深度或指定轨道位置 | 主画面与空间位置同步；显示是否发生尺寸补偿 |
| 激活主取景后滚轮 | 允许时改变焦距 | “原地变焦”提示；不同时移动相机 |
| 激活主取景后 Shift＋滚轮 | 允许时前后移动拍摄相机 | 位移轨迹；D12 联动模式显示自动焦距 |
| 空间视图空白处拖动 | 自由观察模式下环绕观察相机 | 主取景保持不变；俯视/侧视模式使用二维平移 |
| 空间视图滚轮 | 调整观察范围 | 不修改拍摄焦距 |
| D10“原地转向”手柄 | 固定拍摄位置，改变朝向 | 显示方向扇形与“位置未变” |
| 数值输入、方向按钮 | 与手势执行同一条状态操作 | 同样经过范围和约束校验 |
| Esc | 取消当前拖动或退出浮层 | 拖动回滚至开始状态 |
| Ctrl/Cmd＋Z、重做快捷键 | 撤销/重做一次完整编辑 | 一次拖动作为一步，不按每帧记录 |
| 空格 | 聚焦视图区时播放/暂停当前演示 | 在文本输入框内不拦截 |

滚轮接管只发生在用户已激活的视图区；离开或失焦后恢复网页滚动。物体拖动期间停用观察相机控制；松开和取消时恢复，避免一个手势同时改变物体和相机。

主取景内不使用无法判断深度方向的任意抓取。深度通过明确滑块或空间视图手柄控制；所有手势都有可见控件替代。

### 3.3 视觉反馈分层

| 层级 | 默认状态 | 内容 |
| --- | --- | --- |
| 直接反馈 | 开启 | 选中轮廓、当前变化值、操作提示、空间视图同步 |
| 几何测量 | 选中对象时开启 | 光轴深度、实际尺寸、投影高度占比、D10 对齐误差 |
| 分析叠层 | 用户开启 | 投影框、锚点、射线、原位置虚影、地平线、深度伪彩、视锥 |
| 解释信息 | 可折叠 | 当前参数如何影响投影、使用条件、简短公式 |

用户拖动期间，画面应逐帧响应；数值文字和曲线可限制为 10–20Hz 更新。数值是几何或渲染模型的结果，不生成无依据的“立体感强度”“错觉成功率”。

## 4. D09：深度线索控制室

### 4.1 场景基线

世界单位为米，Y 向上，默认拍摄方向为 −Z。

- 相机：`C=(0,1.6,0)`，朝向 −Z，焦距 35mm，画幅 36×20.25mm。
- 地面：`y=0`，世界尺度网格；远处可见侧墙与门框参照。
- A/B/C 三个直立目标底边中心分别为 `(-1,0,-6)`、`(0,0,-10)`、`(1.25,0,-16)`。
- 标准测量目标高 1.4m、宽 0.8m，与相机成像平面平行；可切换为相同位置的几何人偶。
- 精确的画面高度补偿仅在平面标准目标上启用；切换到人偶时保留当前实际高度、退出补偿并提示“已切换为自由尺寸”。人偶模式使用实际投影测量，并标明其包围范围。

### 4.2 控件与实际行为

| 控件 | 范围 / 初始值 | 实际改变 | 可视化反馈 |
| --- | --- | --- | --- |
| 地面网格 | 开；网格边长 0.25–2m，初始 1m | 地面图案，不改变地面和目标坐标 | 远近网格投影密度；可标一格的世界尺寸 |
| 网格对比度 | 0–1，初始 0.45 | 仅图案对比 | 主图实时变化；参数差异条 |
| 投射阴影 | 开/关，初始开 | 投射/接收阴影 | 阴影出现消失；光源和物体漫反射条件保持 |
| 场景雾 | 密度 0–0.08 m⁻¹，初始 0 | 固定雾色与相机深度相关的混合 | 远景变化；中心点透过率示意 |
| 遮挡板 | 开/关；X 为 −2～2m | 增删/移动真实竖板 | 正常深度遮挡、空间视图中的前后关系 |
| 遮挡板宽度 | 0.2–1.8m | 几何宽度 | 轮廓截断变化；不显示未经计算的“遮挡百分比” |
| 目标近远 | 光轴深度 3–24m | 目标位置 | 投影大小、地面位置、距离线同步 |
| 目标高度 | 0.4–4m，宽高比锁定 | 实际几何大小 | 实际高度与画面占比并列 |
| 尺寸关系 | 自由 / 同实际高度 / 补偿画面高度 | 明确的对象尺寸规则 | 自动项只读，显示被修改的真实高度 |
| 环境参照 | 地面、侧墙、门框各自开关 | 对应物体可见性 | 开关旁显示受影响对象 |
| 相机横移 | X 为 −1～1m | 拍摄位置，朝向固定 | 各目标相对起点的屏幕位移箭头 |

遮挡板放在 B 前方，基线中心约 `(0,1,-8)`；开启它不会移动 B。只隐藏遮挡板不等于场景里所有遮挡都消失。

尺寸模式规则：

- “同实际高度”：一个主高度控制三个目标，显示各自不同的画面高度。
- “补偿画面高度”：以参考 `H_ref=1.4m、d_ref=10m`，设置 `H_i=H_ref×d_i/d_ref`，宽度同比例变化，底边仍落在地面。
- 深度 3–24m 对应补偿高度 0.42–3.36m，全部落在目标高度范围内；补偿时高度控件只读，退出后保留当前尺寸。
- 该模式名称必须说明修改了实际尺寸；它保留了底边位置等其他线索。移动相机横向不改变这些深度；如果修改焦距，三者仍等画面高度，但共同占比会变化。

### 4.3 四个预设

| ID | 名称 | 内容 |
| --- | --- | --- |
| `d09-full` | 完整片场 | 默认三目标、网格、门框、投射阴影；无雾，遮挡板关闭 |
| `d09-minimal` | 少参照 | 目标位置不变；地面/墙/门框隐藏，无雾、无投射阴影，标注这是多条件变化 |
| `d09-equal-image` | 画面一样大 | 保留默认深度，按深度补偿实际尺寸；打开侧视尺寸尺 |
| `d09-conflict` | 大小与远近竞争 | A/B/C 高度 0.8/1.4/2.8m；位置不变，可横移观察 |

每项线索另设“按住看关闭状态”的短暂预览，松开恢复；预览不写入撤销历史。对象拖动时禁用该预览，避免两个临时状态互相覆盖。

### 4.4 特有视觉反馈

- 对象卡并列显示：真实高度、光轴深度、到相机中心的直线距离、投影高度占画面百分比。
- 横移时画出每个目标中心的起点、终点和箭头；可显示 `Δx / 画面宽度`，说明参照是固定朝向的相机。
- “深度伪彩”显示当前拍摄相机的深度场，仅作几何解释。进入时显示图例，不把伪彩画面当作原始视觉刺激。
- 空间视图可以分别隐藏墙体/地面，以便看见被遮挡目标；这只改变解释视图，不影响主取景。
- 雾指标若采用 `T=exp[-(ρd)²]`，必须与最终选择的 FogExp2 着色实现及其深度定义一致；在开发时对照锁定的 Three.js 版本验证。它是模型值。

## 5. D10：强迫透视片场

### 5.1 体验与模式

初始提供一个近处托架和远处球体，从参考机位看球像放在托架上。旁边空间视图直接显示它们实际分离；用户可以随时隐藏空间图，只看拍摄效果。

| 模式 | 可改参数 | 自动保证 | 在界面中说明 |
| --- | --- | --- | --- |
| 自由摆拍 | 物体位置、尺寸、拍摄机位与焦距 | 不自动对齐 | 显示锚点误差，适合自行调节 |
| 锚点对齐 | 参考画面接触点、目标深度、目标尺度 | 指定两个锚点在参考相机中投影重合 | 自动修改了目标位置；不保证整个轮廓或真实接触 |
| 投影保持缩放 | 射线尺度系数 `k` | 在参考相机下保留目标整组顶点的理想投影 | 距离、大小、离地高度同时改变 |

“编辑摆拍”和“移动机位观察”是可随时切换的操作状态。进入移动观察后冻结场景几何和自动对齐解算，当前相机可以移动；否则软件会不断修复机关，失去视点变化的效果。

### 5.2 参数与操作

| 控件 | 建议范围 | 主画面反馈 | 空间/数值反馈 |
| --- | --- | --- | --- |
| 近/远锚点深度 | 近 4–10m；远 10–24m，至少间隔 2m | 画面尺度与接触位置变化 | 两点深度和实际间距 |
| 物体尺度 | 0.25–3 倍 | 投影轮廓变化 | 世界高度和当前倍数 |
| 接触点拖动 | 成像框内二维位置 | 两色锚点与连线实时更新 | 显示实际使用的本地锚点 |
| 投影保持系数 | `k=0.5–2` | 参考取景中的几何投影保持 | 旧位置虚影、新几何、距离与大小联动 |
| 横移 / 升降 | X ±1m，Y ±0.5m，相对参考位置 | 接触点逐渐分离 | 相机轨迹与误差曲线 |
| 原地转向 | 相对参考 yaw/pitch 各 ±15° | 取景移动；同射线锚点仍保持重合 | 方向扇形，位置读数不变 |
| 原地变焦 | 18–100mm | 取景范围改变；共线锚点仍重合 | 视锥变窄/变宽 |
| 回参考机位 | 一键 | 回到保存的相机位置、朝向与焦距 | 只恢复相机，不重置用户摆拍物体 |
| 设为参考机位 | 显式按钮 | 更新校准条件 | 提示哪些自动约束将以新相机为基准 |

深度与物体尺度的表列范围用于手动摆拍；投影保持模式中二者由基线和 `k` 派生，只读显示。例如基线深度 18m、`k=2` 时为 36m，不可截断为 24m。派生值须满足相机裁切范围及有限数值约束；返回自由编辑时，控件范围扩展以包含当前值，避免几何跳变。

锚点对齐模式下，拖动的是两个对象共用的参考画面接触点；保持各自深度和尺度，同时解算两个根节点。自由摆拍模式中只移动所选对象，不自动维持接触。

“设为参考机位”是可撤销的原子操作：先固化当前世界变换，再保存当前拍摄相机，重建 `P0、S0、R0`，最后令 `k=1`。该操作本身不移动几何；只有下一次明确启用约束或调整参数才重新求解。

约束不可同时满足时，显示具体原因，例如“当前对齐需要物体离地 0.3m”。投影保持模式使用悬空几何和暗背景；不同时宣称严格保持投影与脚部始终落在原地面。

### 5.3 锚点对齐算法

参考相机位置为 `C0`，单位右、上、前向量为 `r、u、F`；NDC 坐标 `(nx,ny)` 均为 −1～1，Y 向上。给定垂直/水平视场角 `θv、θh` 及光轴深度 `d`：

```text
Q = C0
  + nx × d × tan(θh/2) × r
  + ny × d × tan(θv/2) × u
  + d × F

物体根节点位置 t = Q − R(S × a_local)
```

`a_local` 是球底、托架顶端等真实本地锚点；`R、S` 为当前旋转和缩放。首版实验对象挂在无额外变换的统一根节点下，避免混用本地与世界坐标。

把两个对象中心对齐不能替代接触点对齐。拖动屏幕锚点使用参考相机解投影，不使用空间观察相机。

### 5.4 沿射线移动并保持投影

以参考相机中心为变换中心，对原始世界位置 `P0` 和原始尺度 `S0` 计算：

```text
P(k) = C0 + k × (P0 − C0)
S(k) = k × S0
R(k) = R0
```

每一帧都从保存的 `P0、S0` 求值，不能把上帧结果反复乘 `k`。在固定理想透视相机下，每个顶点的 `x/d、y/d` 不变，因此投影保持；这是投影几何推论。

验证场景使用不受光材质、无雾无阴影、无其他物体遮挡。投影几何不变，不保证任意有光照、雾和遮挡的场景最终像素也完全一样。

### 5.5 视点误差与可交互地图

主图用两种颜色标出锚点，连接线随分离量伸长。反馈区显示：

- 投影对齐误差：锚点距离占画面高度百分比。

- 当前相机相对参考位移；世界尺寸比、锚点深度比、投影高度比。

在相机朝向固定且两锚点原先重合的情况下，水平平移 `δx` 产生的分离量：

```text
f_px = 1080 × focalLengthMm / 20.25
Δpx = f_px × abs(δx) × abs(1/dA − 1/dB)
```

初始 `f=35mm、dA=6m、dB=18m`，侧移 `0.1m` 应分离约 **20.7407 参考像素**，即 **1.92044% 画高**。仅在相机中心原地旋转或变焦，不会拆开原本共线的两个锚点；它们可能移出取景框，出框时标“不可见”。

**视点误差地图**：按参考相机的右、上向量，在 `C0+a×r0+b×u0` 取 21×21 个位置，`a、b` 均为 ±0.5m；使用参考朝向、参考焦距和当前冻结几何计算误差。点击地图进入移动观察状态，并同时应用所选位置、参考朝向与参考焦距，使实际画面对应地图预测。用解析投影计算 441 个点，不渲染 441 张图。

## 6. D12：机位与焦距拆解台

### 6.1 标准片场

- 目标是高 2m 的标准立面，中心 `S=(0,1,0)`；背景测量立面同高，中心 `(3,1,-8)`。
- 拍摄相机 `C=(0,1,d)`，始终朝 −Z；初始 `d=6m、f=35mm`。
- 两立面在不同横向位置显示，避免完全遮挡；记录高度所用的上下基准点必须同深度。
- 场景可增加门框、圆柱和人物轮廓帮助观察前后关系；精确数值仍使用明确标记的标准立面。
- 固定画幅 36×20.25mm、相机 `zoom=1`，不启用镜头畸变、景深或自动取景。

### 6.2 三种编辑模式

| 模式 | 可操作项 | 锁定/派生项 | 实时观察 |
| --- | --- | --- | --- |
| 原地变焦 | 焦距 18–100mm | 机位和朝向锁定 | 取景范围、视锥和主体画面大小变化 |
| 固定焦距移动机位 | 距离 3–18m | 焦距锁定 | 前后景相对比例、遮挡和画面大小变化 |
| 保持主体画面高度 | 距离为唯一驱动量 | 焦距由约束计算，只读 | 主体占比保持，背景相对大小变化 |

切换模式以当前状态为起点。进入“保持主体画面高度”时锁定当前目标占比 `q0`，显示锁定值；不悄悄跳回默认 57.61%。标准预设使用默认值，以便验收。

空间视图可以观察和测量，首版标准模式不允许自由修改拍摄朝向或随意旋转测量立面。这样各控制的含义和公式保持明确；自由三维摄影属于后续扩展。

### 6.3 联动公式与边界

对与成像平面平行、高 `H`、光轴深度 `d` 的标准立面，投影高度占画面比例为：

```text
q = f × H / (sensorHeight × d)

固定 q0 后：
f(d) = q0 × sensorHeight × d / H

在默认基准下：
f(d) = 35 × d / 6
```

只允许“移动机位 → 求焦距”的单向联动，防止两个滑块互相更新。距离滑块有效区间取 `[3,18]m` 与焦距 `[18,100]mm` 推导区间的交集。默认基准的可行距离约 **3.085714–17.142857m**。

到达边界时停止在最后有效状态，并显示“已达焦距范围，主体占比保持”。不能先截断焦距、继续移动机位却仍显示锁定成功。若用户载入的状态本身不满足约束，应提示选择恢复有效状态或关闭联动。

### 6.4 具体视觉反馈

- 主取景标出主体上下基准线和背景上下基准线，旁边显示画面高度百分比。
- 空间视图同步显示摄影机轨道、视锥、目标平面、背景平面以及距离尺。
- 四个核心读数：焦距、垂直/水平视场角、主体画面占比、背景/主体投影高度比。
- 曲线区横轴为相机距离，显示焦距曲线与前后景投影比曲线；两者用分开的纵轴/小图，避免单位混用。
- 拖动时间轴时，游标与主画面同步；悬停曲线显示对应位置，但只有点击/拖动游标才修改场景。
- “对齐主体比较”是对 A/B 图像的显示缩放，不改变原始相机，明确显示缩放倍数和裁切范围。

### 6.5 同机位裁切比较

保存同机位、同朝向的广角 A 和长焦 B。将 A 中央裁切并按 `fB/fA` 等比例放大，可与 B 的相同取景范围叠加比较；仅对理想透视、同画幅且无偏移的条件启用。

如果用户 A/B 的机位、朝向或目标几何不同，该操作仍可作为“对齐主体显示”，但不得标为“同机位等价裁切”。界面需要显示变化项，避免把不同条件混成同一比较。

理想投影下固定机位改变焦距，前后物体投影尺寸比中的焦距因子相消；移动机位才改变它们的相对深度。上述比较是基于投影几何的推导，可参照 [PBRT 投影相机模型](https://www.pbr-book.org/4ed/Cameras_and_Film/Projective_Camera_Models)。

## 7. 共用的对照、动画和保存功能

### 7.1 A/B 对照

每模块保留 A/B 两个快照槽。快照包含完整实验参数、拍摄相机、对象变换、约束状态、快照时间和固定分辨率预览。

- 两张图均以固定 16:9 保存，提供左右并列、拖动分割线和按住切换三种看法。
- A/B 都是冻结快照；用户继续编辑时显示“当前状态尚未覆盖 B”，避免一边静态一边偷偷实时。
- 差异列表显示真正变化的字段，自动派生项也列出，例如“距离 6→12m；自动焦距 35→70mm”。
- “恢复 A/B”先保存当前撤销点，再加载状态；普通查看不修改当前实验。
- 辅助标记是否包含在截图中可选；同一组 A/B 使用相同标记策略。

### 7.2 动画时间轴

首版支持三种确定性演示轨迹，不要求实现通用动画编辑器：

| 模块 | 轨迹 | 计算原则 |
| --- | --- | --- |
| D09 | 固定朝向横移 `x=-0.8→0.8m`，默认 5 秒 | 场景冻结，逐时刻计算相机位置与投影位移 |
| D10 | 从参考位侧移 `x=0→0.5m`，默认 4 秒 | 冻结摆拍几何和对齐求解，只移动当前拍摄相机 |
| D12 | 默认 `d=6→12m`，6 秒 | 每一时刻根据 `d(t)` 求 `f(t)`，保持占比 |

统一提供播放、暂停、循环、0.25/0.5/1/2 倍速和进度拖动。拖动滑块直接编辑时，先暂停并以当前动画姿态作为编辑起点；页面失焦暂停，返回后不跳过大段时间。

动画从归一化 `t∈[0,1]` 和保存的起点状态求值，允许重复定位到同一画面。暂停后的数值、截图与再次恢复必须一致。

### 7.3 撤销、复位与导出

- 撤销历史每模块至少 30 步；拖动起点/终点构成一个事务，预设切换和导入也可撤销。
- “恢复当前预设”和“恢复本模块初始状态”分开命名。跨模块操作不清空另一模块的编辑状态。
- JSON 导出保存全部三模块或当前模块；导入前验证结构、版本、数值范围和约束，失败时保留当前状态。
- PNG 导出支持主取景、A/B 并排、主取景＋空间关系。图片附模块名和关键参数，勾选后附公式/测量，不依赖屏幕截图拼接网页滚动区域。
- 本地自动保存最后一次有效编辑状态；导出文件用于跨机器和本地/线上版本迁移。
- 复制链接只包含当前模块的可复现实验条件；A/B 位图、撤销栈和运行日志不放进 URL。

## 8. 统一几何、测量和约束规范

### 8.1 坐标与相机

| 项目 | 规定 |
| --- | --- |
| 世界尺度 | 1 world unit = 1m；右手系，Y 向上 |
| 默认拍摄方向 | 相机局部 −Z；D09/D10 默认场景向世界 −Z 延伸 |
| 有效画幅 | `sensorWidthMm=36`，`sensorHeightMm=20.25`，固定16:9 |
| 镜头 | 焦距是镜头的唯一可写原始量；FOV 派生，`zoom=1`，`filmOffset=0` |
| 裁切面 | 默认 `near=0.05m`、`far=100m` |
| 拍摄框 | 根据容器计算居中16:9矩形；浏览器resize不修改主摄aspect |
| 参考像素 | 测量统一换算到1920×1080；真实交互坐标使用CSS px |

Three.js 的 `PerspectiveCamera.fov` 是垂直视场角，焦距、画幅和 aspect 必须按统一约定求解。可固定 `filmGauge=36、aspect=16/9` 后使用 `setFocalLength`，并以本方案的公式和数字测试验证锁定版本的行为。[官方相机文档](https://threejs.org/docs/pages/PerspectiveCamera.html)

### 8.2 投影定义

世界点经 `camera.matrixWorldInverse` 转为相机坐标 `(xc,yc,zc)`，令 `D=-zc` 为光轴深度。成像框内左上为 `(u,v)=(0,0)`，右下为 `(1,1)`：

```text
verticalFov = 2 × atan(sensorHeightMm / (2 × focalMm))
horizontalFov = 2 × atan(sensorWidthMm / (2 × focalMm))

u = 0.5 + focalMm × xc / (sensorWidthMm × D)
v = 0.5 − focalMm × yc / (sensorHeightMm × D)

referencePx = (1920 × u, 1080 × v)

alignErrorPx = sqrt((1920×Δu)² + (1080×Δv)²)
alignErrorHeightPercent = 100 × alignErrorPx / 1080
```

纯数学函数与 Three.js 实际投影矩阵应相互校验；屏幕标记、误差、截图使用同一解析后的拍摄状态。更复杂的物体直接投影顶点/锚点，不能继续把中心深度公式当作精确轮廓公式。

### 8.3 量的命名与无效情况

- **光轴深度** `D` 用于投影方程；**直线距离** `|P−C|` 是另一列数据，不能混用。
- **投影高度**指指定上下基准点的高度差。旋转或厚度模型的**投影包围范围**另行命名，不等于可见面积。
- 点在相机后方、穿越 near/far 时，返回有类型的无效结果，界面显示原因；不能显示负距离对应的正常投影指标。
- 物体部分出画框是可探索状态，显示“部分出框”与未裁切投影占比；不自动回正相机或缩小物体。
- D10 投影保持校验要求被验证顶点在合法深度范围；超出范围时限制操作并显示原因。
- 锚点误差首先是几何投影关系，不自动证明接触处可见或被观察者识别。辅助点被实体遮住时用虚线并标“几何参考点”。

### 8.4 几何函数的责任

```ts
resolveShotCamera(experiment): ResolvedCamera
projectPoint(worldPoint, resolvedCamera): ProjectionResult
measureProjectedHeight(topAnchor, bottomAnchor, resolvedCamera): MeasureResult
solveAlignedRoot(referenceCamera, ndc, depthM, localAnchor, rotation, scale): Vec3
scaleAroundCamera(referenceCamera, baselineTransform, k): Transform
solveDollyFocal(distanceM, targetHeightM, lockedQ): number
getDollyDistanceBounds(focalBounds, distanceBounds, targetHeightM, lockedQ): Range
compareSnapshots(a, b): ParameterDiff[]
```

这些函数不读取 DOM，不直接修改 Three.js 对象，不依赖 React。输入不可变、输出可重复，便于数值测试和状态复现。

## 9. 前端技术架构

### 9.1 选定技术栈

| 层 | 采用方案 | 原因 |
| --- | --- | --- |
| 页面与控件 | React + TypeScript | 组织三模块、参数面板、快照、导出和响应式界面 |

| 状态 | Zustand + 纯函数约束层 | UI和渲染器订阅同一数据来源，原始数据可序列化 |
| 输入验证 | Zod | JSON与URL数据的结构、枚举、有限数值和范围检查 |

| 数学测试 | Vitest | 投影、联动、约束和状态往返验证 |
| 浏览器验证 | Playwright | 验证拖动、resize、快照、导入导出与子路径入口 |

实现开始时选兼容的稳定版本，写入 `package.json`、锁文件与 README；使用受当前 Vite 支持的 Node LTS，并记录具体版本。运行时资源全部来自构建产物，不使用在线 CDN 或外部 API。

当前 Three.js WebGLRenderer 以 WebGL2 为基础。初始化失败时展示可读说明和静态参考图，保留方案说明与数据导出入口，避免白屏。[WebGLRenderer 官方文档](https://threejs.org/docs/pages/WebGLRenderer.html)

### 9.2 一个渲染器，两个联动场景

使用一个 Canvas 与一个 WebGLRenderer，以 viewport/scissor 绘制：

1. **拍摄场景**：真正用于主取景的材质、灯光、雾、遮挡与目标。
2. **空间解释场景**：同一状态派生出的简化几何、相机模型、视锥、尺寸尺、参考虚影；可独立剖开墙体。

两场景共享适合复用的几何资源，但不共享会互相污染的可变对象变换或临时材质状态。解释视图的开墙、着色与辅助线不会改变主取景。

模块适配器把同一 `ResolvedExperiment` 应用到两个场景。每一帧的主图、空间图和几何叠层使用同一个解析版本；文字/曲线限频时，延迟不超过约100ms，并在拖动结束后立即刷新。

官方多视口示例可作为viewport/scissor实现参考：[Three.js Multiple Scenes](https://threejs.org/manual/pages/multiple-scenes.html)。

### 9.3 视口、DPR和命中坐标

- Canvas覆盖实验工作区，DOM视口容器提供事件区域；右侧面板与反馈图表是普通DOM。
- 使用 `ResizeObserver` 缓存工作区及视口尺寸；页面滚动/布局改变时更新位置缓存。
- `setPixelRatio(min(devicePixelRatio,1.5))` 为初始策略；`setSize`、`setViewport`、`setScissor` 在屏幕渲染路径统一使用逻辑像素，不在业务层再次乘DPR。
- DOM的顶部坐标转换为WebGL底部坐标：`y = canvasBottom − viewportBottom`。
- Raycaster的NDC来自**实际16:9成像矩形**。黑边点击不命中物体，不使用整个窗口或外层卡片尺寸。
- 导出RenderTarget具有独立的明确像素尺寸，不能直接套用屏幕DPR路径。
- 每个可见视口在scissor限定区域内清理颜色/深度；隐藏视口跳过渲染。

对应基础用法见 [Three.js响应式渲染](https://threejs.org/manual/pages/responsive.html)。

### 9.4 操作控件与资源生命周期

`OrbitControls`只绑定空间观察视图的事件容器；主摄由本方案的滑块、轨道和转向操作控制。`TransformControls`只用于明确允许的对象操作，拖动时暂停同区域的观察控件。[OrbitControls](https://threejs.org/docs/pages/OrbitControls.html)、[TransformControls](https://threejs.org/docs/pages/TransformControls.html)

模块切换取消pointer capture、停止动画、解除事件订阅，防止旧模块继续修改状态。几何/材质资源明确归属，销毁不再使用的资源；React开发模式重复挂载不能造成重复Canvas、事件或动画循环。

### 9.5 渲染与视觉稳定性

- 首版默认固定照明、固定显示转换；不启用自动曝光、自动构图、景深、运动模糊或屏幕空间环境遮蔽。
- D09控制投影时保留物体基本明暗着色；D10投影保持的验证预设使用Unlit材质。
- 网格按世界坐标生成，远处做必要的抗锯齿，避免闪烁纹理抢占注意；显示的网格尺寸仍是真实世界尺度。
- 辅助轮廓以共享投影和SVG/线段绘制为主，不必为选择对象增加全屏后处理链。
- 所有颜色输出使用明确的一次显示编码；屏幕和PNG导出沿用相同路径。数值指标不依赖“从颜色猜距离”。

## 10. 状态结构、事件和存储

### 10.1 数据结构骨架

以下是实现契约骨架，允许按模块细化字段，但需保留原始状态与派生状态的分工。

```ts
type ModuleId = 'd09' | 'd10' | 'd12';
type Vec3 = [number, number, number];
type Quat = [number, number, number, number];

interface CameraInput {
  position: Vec3;
  quaternion: Quat;
  focalMm: number;
}

interface Transform {
  position: Vec3;
  quaternion: Quat;
  scale: Vec3;
}

interface SceneObject {
  id: string;
  kind: 'card' | 'figure' | 'sphere' | 'support' | 'occluder';
  transform: Transform;
  anchors: Record<string, Vec3>; // 本地坐标
}

type LensRig =
  | { mode: 'zoom' | 'dolly'; distanceM: number; focalMm: number }
  | { mode: 'dollyZoom'; distanceM: number; lockedQ: number };

interface AppSave {
  schemaVersion: 1;
  appVersion: string;
  activeModule: ModuleId;
  modules: {
    d09: DepthCueState;
    d10: ForcedPerspectiveState;
    d12: LensRigState;
  };
  ui: ViewPreferences;
}

interface Snapshot {
  id: 'A' | 'B';
  moduleId: ModuleId;
  capturedAt: string;
  state: ExperimentState; // 深拷贝，不持有可变场景引用
  previewKey?: string;   // 位图单独管理，不写进URL
}
```

`DepthCueState`至少包含目标变换、线索开关、纹理尺度、雾密度、遮挡板、拍摄相机、尺寸模式与参考尺寸。补偿模式以约束作为权威来源，不同时维护第二份独立可写高度。

`ForcedPerspectiveState`至少包含对象、本地锚点、参考相机、当前拍摄相机、编辑模式、编辑/观察阶段、投影保持基线和 `k`。

`LensRigState`使用上面的判别联合；联动模式只保存距离与锁定占比，焦距由解析器计算，避免存在两份相互矛盾的“真实焦距”。

`ViewPreferences`包含空间视图模式、面板开合、辅助层和观察相机。它可以保存为UI偏好，但不进入实验差异的科学参数列表。

### 10.2 统一事件路径

```text
用户操作
  → 类型化Action
  → 校验范围与当前约束
  → 更新实验原始状态
  → resolveExperiment得到相机、几何、指标
  → 同一解析结果更新主场景 / 空间场景 / 辅助叠层
  → 拖动结束提交历史、自动保存
```

关键Action包括：`selectObject`、`setCue`、`moveObject`、`setFocalLength`、`setCameraPosition`、`setLensMode`、`captureReference`、`enterObservation`、`setRayScale`、`seekAnimation`、`captureSnapshot`、`restoreSnapshot`、`loadPreset`。

D10进入观察时将当前求解结果固化成对象变换，暂停自动解算，保留参考相机。返回编辑时恢复参考拍摄机位，以当前对象重新建立基线、`k=1`，自动对齐由用户重新开启，避免旧求解器跳变场景。

渲染器不直接回写业务对象。拖动中的临时姿态放在交互事务中，UI和渲染均从同一事务解析；提交后进入正式状态。动画不按帧写撤销栈或localStorage。

### 10.3 数据保存与链接

| 项目 | 约定 |
| --- | --- |
| 自动保存 | 编辑停止后约500ms去抖，保存最近有效状态 |
| 存储Key | `stereo-lab:<规范化部署路径>:state:v1`；同域不同仓库不冲突 |
| 存储失败 | 页面继续使用内存状态，提示可导出JSON；不伪报已保存 |
| URL | 单入口hash，例如 `#m=d12&p=d12-dolly-zoom&v=1` |
| 自定义参数链接 | hash中放紧凑、版本化的当前模块参数；总长建议≤8KB，超出改用JSON导出 |
| 导入限制 | 白名单字段、有限数值、合法枚举、约束一致；文件上限建议256KB |
| 恢复顺序 | 有效分享链接优先；其次本地保存；最后默认D09预设 |
| 损坏数据 | 提示失败原因并回到上一个有效状态；未知版本不静默解释 |
| 更新URL | 编辑过程中用replaceState，不让每次拖动新增历史记录 |

保存属于浏览器当前origin；localhost与GitHub Pages不自动同步，JSON用于迁移。拖动/拍摄时不采集身份信息，不需要登录或后端。

## 11. 截图与导出实现

1. 冻结要导出的实验快照和动画时刻。
2. 按固定目标尺寸重新渲染主图；必要时另渲染空间视图。
3. 使用与屏幕一致的显示转换生成可写入PNG的RGBA数据，避免把线性颜色直接当sRGB像素保存。
4. Canvas2D合成各图、基准线、标题、图例和关键参数。
5. 生成Blob并下载，完成后释放临时RenderTarget及Object URL。

通过 `readRenderTargetPixels` 读取的数据原点在左下，Canvas2D合成采用左上原点；转换时对像素行做一次Y翻转，避免导出倒置。屏幕标记与文字本身使用左上坐标，不能跟随图像再次翻转。

主图默认1920×1080；A/B并排默认2560×720，仍保证两张图分别16:9。参考像素读数沿用1920×1080标定，不随导出尺寸悄悄改变。

DOM中的标签不会自动出现在WebGL图像中，必须显式重画。首版避免运行时外部纹理与字体，使用程序化/随包资源。无需长期启用 `preserveDrawingBuffer`，应在导出时单独渲染。[Three.js截图说明](https://threejs.org/manual/pages/tips.html)

导出任务使用独立的离屏场景实例或明确隔离的资源副本，以快照数据构建；不得临时把当前活动场景改成A、读图后忘记恢复。屏幕与PNG在同一标准色块及相机条件下做视觉比对。

## 14. 性能、可访问性和异常处理

### 14.1 性能目标

以下是开发目标，需在实际课堂电脑上记录结果，不代表已实测：

- 1440×900工作区、DPR上限1.5时，拖动和预设动画目标为接近60fps；较弱设备保持可用的30fps，并显示简化模式。
- 首版程序化场景总三角面建议不超过约60k，主光阴影贴图1024；不启用成本高的全屏后处理。
- 首次必要下载目标为压缩后5MB以内；大模型不进入默认包。
- 静止时按需渲染；动画、拖动、惯性观察和导出才请求连续帧。
- 误差地图由CPU解析计算，编辑停止或限频刷新；不创建数百相机渲染任务。
- 自动降低解释视图刷新频率或阴影质量时，保留几何和测量一致，不改变实际焦距、对象尺寸或教学条件。

对比截图只在捕获/导出时渲染，查看A/B使用缓存位图；位图不塞入localStorage。模块销毁和重复进入后内存不得持续线性增长。

### 14.2 可访问性

- 参数都可通过键盘和数值输入操作；滑块有名称、单位、当前值与合理步长。
- 小按钮和触摸目标至少约44px；有可见焦点状态。
- 色彩之外使用字母、文字和线型区别对象及快照。
- 重要提示采用可被辅助技术读出的状态文本，避免动画每帧播报数值。
- 尊重减少动画偏好；默认不自动播放，所有轨迹可手动拖动时间轴。
- 空间图和主图都提供简短文本描述与关键参数表。

### 14.3 异常情况

| 情况 | 处理 |
| --- | --- |
| WebGL2不可用 / 上下文丢失 | 明确说明、静态示意与恢复按钮；保留JSON状态 |
| 窗口缩放或面板折叠 | 重算成像矩形和命中区域，几何/焦距不变 |
| 约束不可解或焦距越界 | 保留最后有效状态，说明具体边界 |
| 对象出框 | 显示出框标记，不自动改镜头 |
| URL/JSON损坏 | 拒绝无效输入，保留当前工作，提供默认预设入口 |
| 存储满或不可用 | 提醒自动保存不可用，继续允许手动导出 |
| PNG生成失败 | 说明失败并保留状态；JSON导出仍可用 |
| 导入或切模块时仍在拖动 | 先取消交互事务和pointer capture，再加载新状态 |

| I04 | 拖动手柄后释放/取消 | 无相机同时移动，无残留拖动或鼠标被锁住 |
| I05 | D09只关闭网格/投射阴影 | 对象和相机状态不变；关闭投射阴影不关闭主光 |
| I06 | D10先对齐再横移 | 几何冻结、误差增加，未被自动求解器持续修复 |
| I07 | D12联动+暂停+拖动时间轴 | 主体占比保持，背景变化；再次定位同一t得到相同状态 |
| I08 | resize、折叠面板、进入A/B | 16:9与焦距不变，投影标记无错位，黑边不能误选对象 |
| I09 | 保存A、改参数、保存B、拖分割线 | 两图稳定冻结；差异列表准确；恢复快照可撤销 |
| I10 | 导出带标记PNG | 图像与文字方向正确；标记、颜色、画幅与屏幕条件一致，文件能正常打开 |
| I11 | 自定义状态分享与JSON迁移 | 新标签/另一来源载入后复现相同条件 |
| I12 | 键盘、触摸模拟与窄屏 | 关键操作均可完成，无只能依靠悬停/右键的功能 |
| I13 | 构建产物在仓库子路径刷新 | 资源、hash恢复、截图和JSON下载正常 |
| I14 | 本地静态服务启动后断外网重开页面 | 资源全部来自本地，三模块可运行 |
| I15 | 多次切模块、导出、撤销与播放 | 无重复动画、残留事件、明显资源持续增长 |

Playwright覆盖可自动化操作；性能、触控手感与课堂投屏清晰度仍需记录实际设备观察。测试对象是已实现功能和关键数学，不建立只复述控件文案的无效测试。
